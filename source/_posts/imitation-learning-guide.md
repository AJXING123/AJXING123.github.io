> 模仿学习（Imitation Learning，IL）让机器人直接从人类示教中学习策略，绕开复杂的奖励设计，是当前机器人操作与具身智能中最常用的技术路线之一。本文从最基础的行为克隆讲起，逐步梳理 DAgger、GAIL、ACT 与 Diffusion Policy，并给出数据采集和工程落地的检查清单。

## 一、模仿学习解决什么问题

假设你要教一个从没进过厨房的人做番茄炒蛋。一种方式是写一份精确的奖励函数：盐放多少加几分、火候大了扣几分，然后让他反复试错；另一种方式是站在旁边做一遍，让他照着学。

机器人学习也面临同样的选择：

- **强化学习（RL）**：定义奖励，让机器人在环境中大量试错。优点是能发现超越人类示教的行为，缺点是奖励函数难设计、探索成本高、真实机器人上试错危险。
- **传统控制**：人工建模动力学，再设计控制器。优点是稳定可解释，缺点是难以处理高维视觉输入和复杂操作。
- **模仿学习**：收集人类示教轨迹，直接学习“看到什么 → 做什么”的映射。优点是不需要奖励函数，数据利用率高；缺点是受示教质量限制，容易过拟合。

| 维度 | 传统控制 | 强化学习 | 模仿学习 |
| --- | --- | --- | --- |
| 输入 | 状态、模型 | 奖励、环境交互 | 人类示教轨迹 |
| 是否需要奖励 | 否 | 是 | 否 |
| 数据成本 | 低 | 极高（试错） | 中（示教采集） |
| 安全性 | 高 | 真实环境风险高 | 较高 |
| 泛化能力 | 依赖建模 | 较强 | 依赖数据多样性 |

模仿学习的核心假设是：**如果示教数据足够多、足够多样，策略就能学到人类行为中的共性规律，并在相似状态下做出合理动作。**

## 二、形式化定义：从观测到动作

把机器人操作看成一个序列决策问题：

- 观测 `o_t`：相机图像、关节角度、末端位姿、夹爪状态等。
- 动作 `a_t`：关节目标位置、末端增量、夹爪开合等。
- 策略 `π(a | o)`：给定观测，输出动作或动作分布。
- 示教数据集 `D = {(o_i, a_i)}`：由人类遥操作或动捕采集得到。

行为克隆的目标非常直接：

```text
min_θ  E_{(o, a) ~ D} [ L( π_θ(o), a ) ]
```

其中 `L` 可以是均方误差、L1 损失，或对动作分布计算负对数似然。直观理解就是：**在示教出现过的观测上，让策略输出尽量接近人类动作。**

但这里有一个关键问题：训练时策略只见到示教数据中的观测分布，部署时却会进入自己造成的状态。只要策略在某一步出现小误差，下一步观测就会偏离示教分布，误差可能继续放大。这就是模仿学习中最核心的**分布偏移（distribution shift）**问题。

## 三、行为克隆：最直接的做法

行为克隆（Behavior Cloning，BC）把策略学习当成普通的监督学习：

1. 采集若干条示教轨迹。
2. 把每一帧的观测和动作组成训练样本。
3. 用回归或分类损失训练网络。
4. 部署时每个控制周期调用一次策略。

一个最小的 PyTorch 示例：

```python
import torch
from torch import nn

class BCPolicy(nn.Module):
    def __init__(self, obs_dim, act_dim, hidden=256):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(obs_dim, hidden),
            nn.ReLU(),
            nn.Linear(hidden, hidden),
            nn.ReLU(),
            nn.Linear(hidden, act_dim),
        )

    def forward(self, obs):
        return self.net(obs)

def train_step(policy, optimizer, obs, act):
    pred = policy(obs)
    loss = nn.functional.l1_loss(pred, act)
    optimizer.zero_grad()
    loss.backward()
    optimizer.step()
    return loss.item()
```

这段代码只演示了最核心的监督学习流程。真实系统中，`obs` 往往包含多路相机图像和机器人本体状态，需要分别用 CNN 或 ViT 编码后再融合。

BC 的优点是简单、训练稳定、推理快；缺点是：

- **误差累积**：单步误差会在长序列中放大。在简化假设下，累积误差可能随任务长度呈二次增长，直观上就是“越走越偏”。
- **多模态动作**：同一个观测下人类可能有多种合理动作，直接用 L1/MSE 回归容易学到“平均动作”，导致机器人犹豫或卡住。
- **因果混淆**：网络可能学到与动作无关的虚假相关性，例如把“相机画面中物体的位置”误当成“动作指令”。
- **数据覆盖不足**：示教中没有出现过的状态，策略没有参考答案。

## 四、DAgger：让专家纠正自己的错误

DAgger（Dataset Aggregation）针对的正是分布偏移问题。它的思路是：**让策略自己跑，跑偏时请专家纠正，然后把纠正后的数据加入训练集。**

算法流程：

1. 用初始示教数据训练一个策略 `π_1`。
2. 让 `π_1` 在环境中执行，记录它访问到的观测。
3. 在每个观测上请专家给出“正确动作”。
4. 把新数据加入数据集，重新训练 `π_2`。
5. 重复上述过程。

目标可以写成在策略自身访问分布上的监督学习：

```text
min_θ  E_{o ~ d_{π_θ}} [ L( π_θ(o), π*(o) ) ]
```

其中 `π*` 是专家策略，`d_{π_θ}` 是当前策略访问到的状态分布。理论上，在专家可查询、学习器满足无遗憾（no-regret）假设时，DAgger 可以把累积误差从二次量级降到线性量级。

代价也很明显：需要人类持续在线纠正，真实机器人上还要考虑安全。因此工程中常使用一些折中方案，例如只在策略不确定或接近失败时请求专家干预，或者用少量人工纠正数据做微调。

## 五、逆强化学习与 GAIL：学习“为什么”

行为克隆学的是“专家怎么做”，逆强化学习（Inverse Reinforcement Learning，IRL）则试图先恢复专家优化的是什么奖励，再用强化学习求解。

IRL 的基本假设是：专家的行为近似最优，因此可以从示教中推断出一个能解释这些行为的奖励函数 `R(s, a)`。

GAIL（Generative Adversarial Imitation Learning）把这件事做成了对抗训练：

- 判别器 `D` 负责区分“专家数据”和“策略生成的数据”。
- 策略 `π` 负责生成更像专家的行为，骗过判别器。

其目标可以概括为：

```text
min_π  max_D  E_{π_E}[ log D(s, a) ] + E_π[ log(1 - D(s, a)) ]
```

GAIL 不需要显式恢复奖励函数，但训练更不稳定，样本效率通常不如 BC，真实机器人部署也更复杂。它更适合作为理解“模仿学习不只是监督学习”的一个补充视角。

## 六、机器人操作中的关键设计

真正决定模仿学习效果的，往往不是网络结构，而是数据和控制接口。

### 6.1 示教采集方式

| 方式 | 说明 | 典型场景 |
| --- | --- | --- |
| 主从遥操作 | 操作者拖动主臂，从臂跟随 | ALOHA、工业遥操作 |
| VR / 手柄 | 通过 VR 控制器或手柄映射末端位姿 | 数据采集成本低 |
| 空间鼠标 | 6 自由度输入设备 | 精细操作调试 |
| 动捕 / 外骨骼 | 直接捕捉人体动作 | 人形机器人 |

ALOHA 系列使用低成本主从机械臂采集双臂操作数据，操作者通过主臂“手把手”示教，从臂同步执行并记录相机与关节数据。

### 6.2 观测设计

- **多路相机**：全局视角 + 腕部视角通常比单一视角更稳。
- **本体状态**：关节角度、末端位姿、夹爪开合。
- **时间同步**：相机、关节、动作必须对齐，时间戳错位会直接破坏学习信号。
- **标定**：相机内外参、手眼标定、坐标系一致性。
- **观测历史**：堆叠多帧或使用循环网络，帮助策略推断速度与接触状态。

### 6.3 动作空间

常见选择：

- 关节位置 / 速度目标；
- 末端执行器增量位姿；
- 夹爪开合；
- 动作块（action chunk）。

动作空间要与底层控制器匹配。训练时用关节空间，部署时却换成末端增量，是常见的“训练能跑、真机不动”的原因之一。

### 6.4 控制频率

训练数据的采样频率、策略推理频率、底层控制频率必须明确区分。高频策略对算力要求高，低频策略又可能错过接触瞬间。工程上常用“低频策略 + 高频插值/伺服”的结构。

## 七、ACT：动作分块 + Transformer

ACT（Action Chunking with Transformers）是 ALOHA 项目中提出的模仿学习方法，也是当前低成本双臂操作中最常被复现的方案之一。

### 7.1 动作分块

普通 BC 每个控制周期只预测一个动作。ACT 一次预测未来 `k` 步动作：

```text
π_θ(a_{t:t+k} | o_t)
```

这样做有两个直接好处：

- 减少误差逐步累积的机会；
- 降低推理频率，缓解高频推理带来的延迟和抖动。

执行时，机器人只执行动作块的一部分，然后重新预测，形成滚动时域控制。

### 7.2 CVAE 处理示教多样性

同一个观测下，人类示教可能存在多种合理动作。ACT 使用条件变分自编码器（CVAE）引入隐变量 `z`：

```text
π_θ(a_{t:t+k} | o_t, z)
```

训练时，编码器根据观测和真实动作块推断 `z`；推理时从先验分布采样 `z`，或直接取先验均值。这样策略可以建模多种行为模式，而不是简单平均。

训练损失大致包含两部分：

```text
L = L1( a_{t:t+k}, â_{t:t+k} ) + β * KL( q(z | o_t, a_{t:t+k}) || N(0, I) )
```

### 7.3 Transformer 与时间集成

ACT 使用 Transformer 编码观测序列，再由解码器输出动作块。部署时，相邻两次预测的动作块会重叠，ACT 使用时间集成（temporal ensembling）对重叠部分做加权平均，让动作更平滑。

ACT 的优势是结构清晰、训练相对稳定、对双臂精细操作友好；局限是动作块长度、观测配置、数据质量对效果影响很大，跨场景泛化仍需要额外数据或微调。

## 八、Diffusion Policy：把动作生成看成去噪

Diffusion Policy 把动作序列生成建模成扩散过程：从噪声开始，逐步去噪得到未来一段动作。它擅长建模多模态动作分布，在多个机器人操作基准上表现很好。

| 方法 | 核心思想 | 多模态能力 | 推理成本 | 典型特点 |
| --- | --- | --- | --- | --- |
| BC | 单步监督回归 | 弱 | 低 | 简单、易复现 |
| ACT | 动作块 + CVAE + Transformer | 较强 | 中 | 双臂操作常用 |
| Diffusion Policy | 动作序列去噪 | 强 | 较高 | 训练稳定、表达能力强 |

Diffusion Policy 的主要工程挑战是推理延迟。实际部署时通常需要减少去噪步数、使用动作块、做模型加速，或者提高控制层的执行频率来掩盖推理时间。

## 九、从数据到部署：一份检查清单

### 9.1 数据采集

- 每条轨迹是否有明确的开始与结束状态；
- 是否包含失败、恢复和边界情况；
- 相机画面是否稳定，光照和背景是否多样；
- 关节、相机、动作时间戳是否对齐；
- 是否记录语言指令或任务标签；
- 训练集、验证集是否按任务或场景划分，避免数据泄漏。

### 9.2 训练

- 先跑通单步 BC，再上动作块和复杂模型；
- 监控训练损失与验证损失，但不要只看损失；
- 检查动作归一化方式是否与部署一致；
- 检查观测预处理是否在训练和推理时完全一致；
- 固定随机种子，保留可复现的实验配置。

### 9.3 评估

- 成功率：完整任务完成比例；
- 泛化性：新物体、新位置、新光照；
- 鲁棒性：中途扰动、遮挡、人为干预；
- 延迟：从观测到动作的端到端时间；
- 干预率：部署时需要人类接管的频率。

### 9.4 常见误区

| 现象 | 可能原因 | 排查方向 |
| --- | --- | --- |
| 训练损失很低，真机成功率很低 | 分布偏移、数据泄漏 | 检查验证集划分与真机观测分布 |
| 机器人动作犹豫、平均化 | 多模态动作被回归平均 | 尝试 ACT、Diffusion Policy 或离散化动作 |
| 换背景后完全失效 | 视觉过拟合 | 增加背景多样性、数据增强 |
| 动作频率抖动 | 推理延迟与底层控制不匹配 | 动作块、插值、降低推理频率 |
| 夹爪总是提前闭合 | 因果混淆、时序错位 | 检查时间同步与观测历史 |

## 十、学习路径与总结

如果你刚开始接触模仿学习，建议按以下顺序推进：

1. **理解 BC**：用状态输入跑通一个简单的回归策略，观察误差累积。
2. **理解分布偏移**：在同一任务上对比 BC 与 DAgger 的成功率。
3. **进入机器人数据**：用遥操作采集几十条轨迹，处理时间同步与动作空间。
4. **复现 ACT**：先跑通官方代码，再替换成自己的相机与机械臂配置。
5. **评估与迭代**：建立固定测试集，记录成功率、失败类型和干预率。
6. **再扩展**：根据任务需要尝试 Diffusion Policy、多任务训练或语言条件策略。

几个可以帮助自检的问题：

- 为什么行为克隆在训练集上损失很低，部署时仍会失败？
- DAgger 为什么需要专家在线参与？它解决了哪一个分布上的问题？
- ACT 为什么要预测动作块，而不是单步动作？
- CVAE 的隐变量在训练和推理时分别怎么用？
- Diffusion Policy 的多模态建模能力，代价是什么？

模仿学习不是“收集数据 → 训练网络”这么简单。数据质量、观测设计、动作接口、时间同步和评估方法，往往比模型结构更决定最终效果。把这条链路打通，再去追更复杂的模型，成功率会高得多。
